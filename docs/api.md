# HTTP API conventions

Rules every Aether-os HTTP API follows, so that services look and behave alike to Iris, third parties and each other. The OpenAPI specs in `contracts/` must follow them.

Status: the decisions below are agreed; sections marked **Proposal** are not agreed yet. Documentation only: the current specs and services don't follow all of it yet (see Current state).

## Decisions

| Decision | Choice |
|---|---|
| Methods | **Only `GET`, `POST`, `PUT` and `DELETE`. Never `PATCH`.** |
| Versioning | **In the path, starting with `/v1`**: `/v1/organizations/{organizationId}/projects`. |
| IDs | **UUIDs**, for every resource and in every path, payload and event. |
| Errors | **Problem details** (RFC 9457, `application/problem+json`), with our own stable `code`. |
| Pagination | **Cursor-based**: `limit` and an opaque `cursor`; no offsets. |

## Payloads

| Topic | Convention |
|---|---|
| Field names | `camelCase`. References to other resources are `<thing>Id` (`projectId`), never embedded objects by default. |
| Timestamps | ISO 8601 in UTC with `Z` and millisecond precision: `2026-11-15T09:30:00.000Z`. Named `<event>At` (`createdAt`, `approvedAt`). Dates without time: `YYYY-MM-DD`. |
| Durations | Integers with the unit in the name: `timeoutSeconds`, `retentionDays`. No ISO 8601 durations. |
| Enums | Lowercase `snake_case` strings (`awaiting_review`, `changes_requested`). The spec says per enum whether it's open (clients must accept unknown values) or closed. |
| Unset values | **Responses always contain every field**; unset is `null`, never left out. Lists are `[]`, never `null`. Requests follow `PUT`'s rule: every editable field present, `null` to clear. |
| Money | **Decimal strings**, never floats: `"costUsd": "12.345600"` (6 decimals). Stored as `numeric(18,6)` in Postgres and computed with a decimal library. |
| Booleans | Plain `true` / `false`; never nullable (a third state is an enum). |
| Size | Request bodies up to 1 MB by default; larger content goes to Loculus through a signed URL. |

## Methods

| Method | Use | Success |
|---|---|---|
| `GET` | Read a resource or a list. Never changes anything. | `200` |
| `POST` on a collection | Create a resource; the server generates its ID. | `201` with the resource, and `Location` |
| `POST` on an action | A state change or command that isn't "replace the resource": `.../suspend`, `.../publish`, `.../approve`, `.../cancel`, `.../retry`. | `200` with the resource (or `202` if it completes asynchronously) |
| `PUT` | Replace a resource's editable fields as a whole. | `200` with the resource |
| `DELETE` | Delete a resource. | `204` |

Since there's no `PATCH`, there are no partial updates. Changing state goes through **actions** (`POST`), changing content through **`PUT`** with the full representation. This keeps state machines (task, agent version, organization) explicit: no client can move a task to `succeeded` by sending `{ "status": "succeeded" }`.

Rules:

- **`PUT` replaces, it doesn't create.** `PUT` on an ID that doesn't exist is `404`; creation is always `POST`, so IDs are always generated by the server.
- **`PUT` takes the whole editable representation.** A field left out is a validation error (`400`), never "unchanged" and never "cleared"; to clear an optional field, send `null`. Read-only fields (`id`, `createdAt`, `status`, …) may be sent back unchanged and are ignored.
- **Optimistic concurrency.** `GET` returns an `ETag` (the resource's version); `PUT`, `DELETE` and actions accept `If-Match`, and a mismatch is `412 Precondition Failed`. Iris always sends it, so two people editing an automation don't silently overwrite each other.
- **Actions are idempotent where it's natural:** suspending a suspended organization returns `200` with the unchanged resource. An action that isn't valid in the current state is `409` with a domain error code.
- **`DELETE`** returns `204`; deleting something that's already gone is `404`. Resources with a history (agents, automations, projects) are usually **archived** with an action rather than deleted.
- **Creation is idempotent** with an `Idempotency-Key` header where retries are likely (e.g. creating a task, see `../CLAUDE.md`): the same key returns the original result.

## Versioning

- Every endpoint is under a major version: `/v1/...`. Each service versions its own API; `/v1` of Hephaestus and `/v1` of Polis are independent.
- **Within a version, only compatible changes:** new endpoints, new optional request fields, new response fields, new enum values where the spec says the enum is open. Clients must ignore unknown response fields.
- **A breaking change means `/v2`** for the affected endpoints, with `/v1` kept running during a deprecation period. Deprecated endpoints send `Deprecation` and `Sunset` headers (RFC 9745 / RFC 8594).
- The spec's `info.version` is the contract's own semver (bumped on every change); the path version only changes on breaking changes.
- **Exceptions:** paths fixed by external standards are not versioned: Pistis's OpenID Connect endpoints (`/.well-known/openid-configuration`, the JWKS, authorize and token endpoints), and health checks (`/health`). Webhook endpoints for providers are versioned like everything else (`/v1/webhooks/github`), so they can change format later.

## IDs

- Every resource ID is a UUID: organizations, projects, agents and versions, tasks, executions, artifacts, documents, templates, automations, events (`eventId`).
- **Generated by the server**, on `POST`. Clients never choose IDs (they choose idempotency keys).
- **UUIDv7.** Time-ordered UUIDs keep database indexes compact and make IDs sort by creation time; they're still opaque to clients, who must not parse them.
- In OpenAPI: `type: string, format: uuid`. A path parameter that isn't a UUID is `400`; a valid UUID that doesn't exist, or belongs to another organization, is `404` (see the tenancy guard in `identity.md`).
- In Postgres: the `uuid` column type, not `varchar`.
- Human-readable identifiers (organization and project slugs) are **additional** lookups (`/v1/organizations/by-slug/{slug}`), never a replacement for the ID, and never used in references between services.

## Errors

Every error response is a problem details object (RFC 9457) with `Content-Type: application/problem+json`:

```jsonc
{
  "type": "urn:aether-os:problem:organization-suspended",
  "title": "Organization is suspended",
  "status": 409,
  "detail": "Organization 0193… is suspended and can't be changed.",
  "instance": "/v1/organizations/0193…/projects",
  "code": "ORGANIZATION_SUSPENDED",
  "traceId": "4bf92f3577b34da6a3ce929d0e0e4736"
}
```

| Field | Meaning |
|---|---|
| `type` | A URI identifying the kind of problem; one per `code` (Proposal: `urn:aether-os:problem:<code in kebab case>`, and later a docs page per type) |
| `title` | Short, human-readable, the same for every occurrence of the type |
| `status` | The HTTP status, repeated |
| `detail` | Human-readable explanation of this occurrence. For people, never parsed by clients |
| `instance` | The request path |
| `code` | **Our extension:** the stable, machine-readable code clients switch on (`ORGANIZATION_SUSPENDED`, the existing `DomainError` codes) |
| `traceId` | **Our extension:** the request's trace ID, so a user can quote it and an operator finds the trace in Jaeger |
| `errors` | **Our extension, for validation failures:** one entry per invalid field, `{ "pointer": "/name", "code": "REQUIRED", "detail": "…" }`, with a JSON Pointer into the request body (or `parameter` for query and path parameters) |

Status codes:

| Status | When | `code` |
|---|---|---|
| `400` | Validation failed, malformed body, invalid UUID or cursor | `VALIDATION_FAILED` (with `errors`), `INVALID_CURSOR` |
| `401` | Missing, invalid or expired token | `UNAUTHENTICATED` |
| `403` | Authenticated, but missing the permission | `FORBIDDEN` |
| `404` | Doesn't exist, or belongs to another organization (never confirm other tenants' IDs) | `NOT_FOUND` |
| `409` | A domain rule forbids it (the `DomainError` codes) | e.g. `PROJECT_ARCHIVED` |
| `412` | `If-Match` didn't match the current version | `VERSION_MISMATCH` |
| `429` | Rate limited, with `Retry-After` | `RATE_LIMITED` |
| `500` | Unexpected; no internals, stack traces or SQL in the response | `INTERNAL` |
| `503` | A dependency is unavailable (e.g. OPA, failing closed), with `Retry-After` where known | `UNAVAILABLE` |

Rules:

- **One implementation, in Krepis:** an exception filter turns `DomainError`, validation errors (Zod issues from the `ZodValidationPipe`, see `engineering.md`), Nest's HTTP exceptions and unknown errors into problem details, so no service formats errors itself.
- **One schema, in `contracts/`:** a shared `Problem` schema that every spec references for its error responses, and each spec lists the `code`s an operation can return.
- **Codes are contracts:** adding a code is a compatible change; renaming or removing one is breaking.
- **`detail` is safe to show** but is not translated and not stable; Iris shows its own message per `code` where it has one.

## Pagination

Every list endpoint uses **cursor (keyset) pagination**.

Request:

| Parameter | Meaning |
|---|---|
| `limit` | Page size, 1–100, default 50 |
| `cursor` | Opaque cursor from the previous page's `nextCursor`; absent for the first page |
| filters, `sort` | Per endpoint, from an allow-list (Proposal: `sort=createdAt` / `-createdAt`, default newest first) |

Response:

```jsonc
{
  "items": [ /* … */ ],
  "nextCursor": "eyJrIjpbIjIwMjYtMTEtMTVUMT…"   // null on the last page
}
```

Rules:

- **Opaque:** a cursor is base64url-encoded JSON (the sort key and ID of the last item, plus the filters and sort it was made with). Clients pass it back unchanged and never build or parse one.
- **Stable under changes:** each page continues after the last item seen (`WHERE (createdAt, id) < (…)`), so items created or deleted meanwhile never cause duplicates or skipped items, unlike offsets. The ID breaks ties, and with UUIDv7 it's itself time-ordered.
- **Bound to its query:** a cursor carries its filters and sort; using it with different ones is `400 INVALID_CURSOR`. To change filters, start again without a cursor.
- **Forward only,** to start with. Iris pages forward ("load more", infinite scroll); a `previousCursor` can be added later as a compatible change.
- **No total count** by default: counting large, changing tables is expensive and the number is stale immediately. Endpoints that really need one (e.g. "3 drafts waiting for review") expose it separately.
- **Signed or validated:** a cursor is checked on decode (shape, types, allowed sort keys) and gives no access by itself; it never bypasses tenancy or permission checks, which apply to every page.

## Current state

- **Methods:** the specs already use only `GET` and `POST`, with actions for state changes (`/suspend`, `/archive`, `/publish`), so nothing to remove. `PUT` and `DELETE` will appear with the first editable resources.
- **Versioning, errors, pagination:** done. Krepis's `configureHttpApp` sets the `/v1` prefix and turns every error into problem details (the shared `Problem` schema is in `contracts/common.openapi.yaml`), and lists use keyset pagination through Krepis's `findPage`. Not yet: `Retry-After` on `429` / `503`, `ETag` / `If-Match`, and `Location` on `201`.
- **Actions:** idempotent where natural in Polis and Hephaestus (suspend, activate, archive, publishing the published agent version return the unchanged resource). Workspace transitions are deliberately strict.
- **IDs:** Polis and Hephaestus generate UUIDv7 in their mappers, store them as `uuid`, declare `format: uuid` and answer `400` for path IDs that aren't UUIDs.
